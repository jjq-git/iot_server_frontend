# 部署凭据轮换与验证

> 最后更新：2026-09-17

## 适用范围

本仓库历史版本曾包含密码式 SSH 部署脚本和固定部署地址。当前版本已经改为：

- 目标信息仅存放在被 Git 忽略的 `.deploy.local`；
- 认证仅使用 SSH Agent 或独立私钥；
- 仓库只保留不含真实主机和凭据的 `.deploy.example`；
- test/prod backend 部署通过 `scripts/deploy.sh` 执行，纯客户端 Demo 通过隔离的 `scripts/deploy-demo.sh` 执行。

删除当前文件不能使历史凭据失效。凭据轮换必须由有服务器或 CI Secret 管理权限的人员完成。

## 轮换顺序

1. 盘点曾使用旧脚本访问的测试和生产环境，以及对应的系统账号、CI 变量和自动化任务。
2. 在目标系统生成用途隔离的新 SSH Key；测试、生产和公开 Demo 环境不要共用同一私钥。
3. 将公钥安装到目标账号，并把私钥保存到受控的 CI Secret、SSH Agent 或本机安全存储。
4. 使用批处理模式验证新密钥可以登录：

   ```bash
   ssh -o BatchMode=yes -i /path/to/new-key deploy@example.com true
   ```

5. 更新本机 `.deploy.local` 或 CI 配置中的主机、用户、目录和 `IDENTITY_FILE`，不得新增密码字段。
6. 分别验证测试、生产和 Demo 部署流程后，撤销旧密码、旧公钥及相关临时授权。
7. 检查目标服务器与 CI 的认证日志，确认没有任务继续使用旧凭据。
8. 在安全工单中记录轮换人员、时间、凭据标识、验证结果和旧凭据撤销证据；不要记录私钥或密码本身。

## 验收证据

- [ ] 测试环境旧凭据已撤销，新 SSH Key 登录验证成功。
- [ ] 生产环境旧凭据已撤销，新 SSH Key 登录验证成功。
- [ ] Demo 环境使用独立 SSH Key，且只允许写入 Demo 静态站点发布目录。
- [ ] CI 和个人自动化任务均不再引用旧密码或旧私钥。
- [ ] `.deploy.local`、`.env.prod`、本地运行状态及 `tmp/` 生成物均未被 Git 跟踪。
- [ ] 安全工单已记录轮换时间和撤销证据，但不包含凭据内容。

## 关于 Git 历史

轮换并撤销旧凭据后，历史中的旧值应当已经失效。若合规要求同时清除历史内容，需要仓库管理员单独安排历史重写、远端强制更新、分支保护调整，以及所有克隆和派生仓库的同步清理。历史重写不能代替凭据轮换，也不应在普通功能提交中执行。
