- **路由 meta** 全部 i18n 化（49 个 `meta.title` + 18 个 `docMeta` + 5 个 `section` 分组），`router.beforeEach` 中翻译后再写 `document.title`
- **通用 UI** i18n 化：[services/ui/confirm.js](../src/services/ui/confirm.js) 默认按钮（common.tip / common.ok / common.cancel）、[api/http.js](../src/api/http.js) 401 / 必改密 toast、[Login.vue](../src/views/Login.vue) 登录提示

- 未覆盖：业务页面表单、表格列头、模块内部 toast 等深层文案（仍以中文为主），后续按需求增量补齐

## 框架说明

- 框架：[vue-i18n](https://kazupon.github.io/vue-i18n/) `^8.x`（Vue 2 必须用 v8，v9+ 仅支持 Vue 3）
- 安装方式：`npm install --save vue-i18n@8 --registry=https://registry.npmmirror.com`
- 入口注册：[src/main.js](../src/main.js) 在创建根 Vue 实例时通过 `i18n` 字段挂载
- 实例配置：[src/locales/index.js](../src/locales/index.js)

## 目录结构

```
src/locales/
├── index.js          # i18n 实例 + setLocale + SUPPORTED_LOCALES + matchBrowserLocale
├── zh-CN.json        # 简体中文（母版）
├── zh-TW.json        # 繁体中文
├── en-US.json        # 英文（美式）
├── de-DE.json        # 德语
├── ja-JP.json        # 日语
├── fr-FR.json        # 法语
├── es-ES.json        # 西班牙语（欧版）
└── ko-KR.json        # 韩语
```

初始语言选择优先级（见 [src/locales/index.js](../src/locales/index.js) `getInitialLocale`）：

1. `localStorage.locale`（用户上次选择，由 `setLocale` 写入）
2. `navigator.language`（浏览器语言，由 `matchBrowserLocale` 完整 + 前缀匹配 8 个 code）
3. 默认 `zh-CN`

## 基本用法

**模板（.vue 的 `<template>`）**

```html
<button>{{ $t('common.ok') }}</button>
<span>{{ $t('errors.E2001') }}</span>
```

**组件 JS / `<script>`**

```js
this.$t('common.save')                  // 当前语言
this.$tc('cart.items', count)           // 复数（可选，按需）
this.$i18n.locale                       // 读取当前 locale
```

**非组件文件（utils / api / services）**

```js
import i18n from '@/locales'
const text = i18n.t('errors.E1004')
```

**切换语言**

```js
import { setLocale } from '@/locales'
setLocale('en-US')   // 自动写 localStorage + 更新 <html lang>
```

## 新增语言步骤

> 当前已涵盖 8 种语言，下面流程仅在再追加新语种（如 `pt-BR`）时使用。

以加葡萄牙语 `pt-BR` 为例：

1. 新建 `src/locales/pt-BR.json`（结构与 `zh-CN.json` 完全一致，缺失 key 会回落到 `fallbackLocale`）
2. 编辑 [src/locales/index.js](../src/locales/index.js)：
   - 顶部 `import ptBR from './pt-BR.json'`
   - `SUPPORTED_LOCALES` 数组追加 `{ code: 'pt-BR', name: 'Português', nativeName: 'Português' }`
   - `messages` 对象追加 `'pt-BR': ptBR`
   - `matchBrowserLocale` 中追加 `if (lang.startsWith('pt')) return 'pt-BR'`
3. [src/components/LanguageSwitcher.vue](../src/components/LanguageSwitcher.vue) 不需要改——它直接从 `SUPPORTED_LOCALES` 渲染下拉项
4. `npm run build` 验证，并在浏览器里切到该语言肉眼检查布局

## 文案 key 命名规范

- 三段式：`<module>.<scope>.<name>`
- 全部小写 + 下划线，避免连字符（JSON path 友好）
- 模块对齐 [src/views/](../src/views/) 子目录或业务领域，例如：
  - `nav.*` / `sidebar.*`：侧边栏 / 顶栏导航文案
  - `route.*`：路由 `meta.title` / `meta.description` / 分组 `section`（详见 [路由 meta i18n 化](#路由-meta-i18n-化)）
  - `auth.*`：登录、找回密码、Token 失效等（含 `auth.session_expired` / `auth.must_change_password_first`）
  - `common.*`：跨页面通用按钮、状态、占位（含 `common.tip` / `common.ok` / `common.cancel`，被 [services/ui/confirm.js](../src/services/ui/confirm.js) 默认引用）
  - `errors.E1004`：后端 API 错误码（详见下节）
  - `hosts.list.title`、`units.form.placeholder.name`：业务页面专属
- 8 种语言 JSON 的 key 集合必须严格一致；缺失时 `fallbackLocale` 回落到 `zh-CN`，生产环境抑制 missing 警告（见 `silentTranslationWarn`）

## 路由 meta i18n 化

> 2026-05-09 commit `6e51a1f` 引入。

[src/router/index.js](../src/router/index.js) 中 **`meta.title` / `meta.description` / `section` 都存 i18n key 而非翻译后的字符串**，由消费方在运行时 `$t()`：

```js
// router/index.js
{
  path: 'devices/hosts',
  name: 'DevicesHosts',
  component: Hosts,
  meta: { title: 'route.hosts.title', icon: 'display' }
}

// router.beforeEach 翻译后再写 document.title
document.title = `${baseTitle} - ${i18n.t(to.meta.title)}`
```

消费方约定：

- **`document.title`**：[src/router/index.js](../src/router/index.js) `beforeEach` 中 `i18n.t(meta.title)` 翻译后写入
- **面包屑**：[src/components/AppBreadcrumb.vue](../src/components/AppBreadcrumb.vue) 在模板里 `$t(item.meta.title)`
- **文档导航页 / 数据模型页**：[src/views/DocPage.vue](../src/views/DocPage.vue) 同样 `$t(meta.title)` / `$t(meta.description)` / `$t(meta.section)`
- **侧栏分组**：[src/components/Sidebar.vue](../src/components/Sidebar.vue) 的测量算宽逻辑也是先 `$t()` 再测量

新增路由时 **必须** 在 8 个 locale JSON 的 `route.*` namespace 下补齐对应 key（zh-CN 是母版，其它语言可暂时填中文，后续翻译公司补齐）。

## 后端错误码 i18n 映射

约定：后端 `APIError` 标准响应 `{ code: "E2001", message: "...", ... }`，前端按 `errors.<code>` 翻译。

实现位于 [src/api/http.js](../src/api/http.js) 响应拦截器，逻辑：

```
1. 拿到 error.response.data.code
2. 查 i18n key `errors.${code}`
3. 命中 -> 写入 error.userMessage（i18n 译文）
4. 未命中 -> 写入 error.userMessage（后端 message 原文）
```

调用方使用：

```js
try {
  await api.login(...)
} catch (e) {
  this.$uiToast.error(e.userMessage || '请求失败')
}
```

新增错误码时，在 `src/locales/zh-CN.json` 和 `en-US.json` 的 `errors` 节下同步添加 `EXXXX` 条目即可，无需改 `http.js`。

## LanguageSwitcher 组件

文件：[src/components/LanguageSwitcher.vue](../src/components/LanguageSwitcher.vue)（旧称 `LocaleSwitcher`，2026-04 后已更名并合入主线）

- **挂载位置**：[src/components/Topbar.vue](../src/components/Topbar.vue) 顶栏，登录后所有页面可切换
- **数据来源**：直接从 [src/locales/index.js](../src/locales/index.js) 导出的 `SUPPORTED_LOCALES` 渲染下拉项，新增语种无需改组件
- **切换实现**：调用 `setLocale(code)` 写 `localStorage` + 更新 `<html lang>`，并触发 vue-i18n 响应式更新；不再 `window.location.reload()`
- 登录页 [views/Login.vue](../src/views/Login.vue) 暂未挂 LanguageSwitcher（未登录场景默认跟随浏览器语言或上次本地选择）

## 常见问题

- **Q: 控制台一直报 `[vue-i18n] Cannot translate the value of keypath ...`**
  - A: 开发环境正常，业务页面深层文案仍未全量翻译；生产环境已通过 `silentTranslationWarn` 抑制。补 key 时在 8 个 locale JSON 都加上对应条目。
- **Q: 切换语言后部分组件没刷新？**
  - A: 模板里直接用 `$t(...)` 是响应式的；JS 里 `i18n.t(...)` 缓存到 data 的不会刷新。LanguageSwitcher 切换语言时只改 `i18n.locale`，**不**做 `window.location.reload()`，所以靠缓存到 `data` / `computed` 里的文案不会自动刷。这种情况要么改成模板里直 `$t(...)`，要么在该值上加一层 `computed { return this.$t(key) }`。
- **Q: 路由 meta 里现在存的是 i18n key（如 `route.dashboard.title`），如果消费方忘了 `$t()` 直接输出会怎样？**
  - A: 在 [src/router/index.js](../src/router/index.js) `beforeEach` 中已统一翻译 `document.title`，但其它消费方（自定义面包屑、菜单组件）若新增需自己包 `$t()`。已知消费方：[AppBreadcrumb.vue](../src/components/AppBreadcrumb.vue) / [DocPage.vue](../src/views/DocPage.vue) / [Sidebar.vue](../src/components/Sidebar.vue)。
- **Q: 为什么用 vue-i18n@8 而不是最新版？**
  - A: 项目是 Vue 2.6.14，vue-i18n@9+ 仅支持 Vue 3。
- **Q: BootstrapVue 内置文案（如分页 "Next/Previous"）能 i18n 吗？**
  - A: 可以，但需要单独配置 `Vue.use(BootstrapVue, { ... })` 的 `BvConfigPlugin`。当前未启用。
