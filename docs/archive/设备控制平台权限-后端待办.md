# 设备控制平台权限后端待办

> 已归档，仅保留历史记录。

> 最后更新：2026-08-14

本文记录“静音仓管理 → 列表 → 设备控制”前端收紧后的后端配套工作。本轮只修改前端，后端代码尚未调整。

## 权限口径

当前系统尚未实现独立的“平台运维”角色，因此本文中的“平台账号”明确指：

```text
role = platform_admin
```

不能只根据 `company_type = PF` 放行，也不能把租户 `admin` 或 `maintainer` 等同于平台账号。后续如果新增平台运维角色，应通过统一权限点扩展，不要在接口中继续增加零散判断。

## 前端已完成

`PodControlPanel` 已按以下规则控制展示和请求：

| 功能 | `platform_admin` | 其他角色 |
| --- | --- | --- |
| 重启设备 | 保持原规则 | `admin`、`maintainer` 保持原规则 |
| 获取状态命令 | 显示并可操作 | 隐藏，前端方法同时拒绝执行 |
| 自定义命令 | 显示并可操作 | 隐藏，前端方法同时拒绝执行 |
| 命令历史 | 显示并请求接口 | 整块隐藏，不请求历史接口 |
| 模块属性控制 | 保持原规则 | 继续按角色和字段权限判断 |

前端限制只用于界面体验，不能作为安全边界。

## 后端 P0 待办

### 1. 限制获取状态命令

以下兼容接口都需要使用同一套命令级权限判断：

- `POST /api/v1/units/{uuid}/status/command`
- `POST /api/v1/pods/{uuid}/status/command`

当请求体中的 `command` 为 `get_status` 时，仅允许 `platform_admin`。非平台账号应返回 `403`，且不能发布 MQTT 消息、不能创建命令记录。

`restart`、`write_attrs` 和模块属性控制暂时保持现有角色与公司写作用域规则，不因本次调整一并收紧。

### 2. 限制自定义命令

任意不在普通命令白名单中的命令只允许 `platform_admin`。当前服务层已有相关判断，但需要补充接口级回归测试，避免后续重构绕过。

`POST /api/v1/units/{uuid}/raw-command` 当前已经要求 `platform_admin`，应保持不变。

### 3. 限制命令历史

将以下接口收紧为仅 `platform_admin`：

- `GET /api/v1/units/{uuid}/commands`

接口仍应先验证角色，再读取资源；非平台账号不得获得命令 ID、命令内容、请求参数、MQTT Topic、ACK 内容或错误详情。

### 4. 收紧 WebSocket 回执

检查设备 WebSocket 的 `command_ack`、命令状态变化等事件。非 `platform_admin` 可以继续接收必要的设备在线状态和业务属性更新，但不能收到完整命令、参数、命令 ID、ACK 原文等命令历史信息。

WebSocket 鉴权必须复用登录账号的实时角色与公司作用域，并在账号停用、角色变化或 scope 变化后失效。

### 5. 审计与安全

- 平台账号执行获取状态、自定义命令时记录操作者、设备 UUID、命令类型、时间、结果和来源 IP。
- 自定义参数按敏感字段规则脱敏，禁止把凭据或密钥明文写入普通应用日志。
- 权限判断必须 fail-closed；缺少角色、角色未知或用户状态异常时一律拒绝。
- 保留设备公司写作用域校验，不能因为是命令接口而跳过资源归属检查。

## 验收用例

| 用例 | 预期 |
| --- | --- |
| `platform_admin` 下发 `get_status` | `2xx`，创建命令记录并发布 |
| `admin` / `maintainer` 下发 `get_status` | `403`，无命令记录、无 MQTT 发布 |
| 非平台账号提交未知/自定义命令 | `403`，无副作用 |
| `platform_admin` 查询命令历史 | `2xx`，返回所属设备记录 |
| `admin` / `maintainer` / `data_entry` / `viewer` 查询命令历史 | `403`，响应不包含历史数据 |
| 非平台账号订阅设备 WebSocket | 可收到必要状态，不包含完整命令回执 |
| 非平台账号重启其写作用域内设备 | 保持当前产品规则 |
| 任意账号操作 scope 外设备 | 按现有防枚举策略拒绝，且无副作用 |
