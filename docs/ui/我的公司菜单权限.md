# “我的公司”菜单权限

> 最后更新：2026-09-02
>
> 适用范围：“我的公司”页面左侧分类菜单、对应页面入口和写操作

## 1. 判断原则

“我的公司”的最终权限由三个条件取交集：

```text
菜单可见 = 公司类型允许 && 用户角色具备页面能力 && 当前公司属于 allowed_companies
允许修改 = 菜单可见 && 用户角色具备动作能力 && 当前公司属于 writable_companies
```

生产授权中，公司类型只决定某项公司级能力是否适用，不能授予用户权限；后端角色只决定操作能力，不能扩大公司数据范围。平台公司中的普通 `admin`、`operator` 不会因为所属公司而成为 `platform_admin`，未知角色或缺少 scope 时必须拒绝访问。Demo 的管理员映射只用于展示标准组合，不是生产授权算法。

## 2. 公司类型适用范围

| 菜单 | 平台公司 | 静音仓生产厂家 | 其他业务公司 | 最终客户 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 公司资料 | ✅ | ✅ | ✅ | ✅ | 当前公司的名称、Logo、联系信息和公司级设置 |
| 公司用户 | ✅ | ✅ | ✅ | ✅ | 是否显示继续由用户角色决定 |
| 界面配置 | ❌ | ✅ | ✅ | ✅ | 平台公司统一审核其他公司的界面，不维护自身定制界面 |
| 文件与资料 | ✅ | ✅ | ✅ | ✅ | 只保存公司级或型号共享资料；单设备文件仍在设备详情中维护 |
| 集成配置 | ✅ | ✅ | ✅ | ✅ | 只放当前公司的第三方连接；平台全局基础设施配置不放在这里 |
| 操作记录 | ✅ | ✅ | ✅ | ✅ | 当前公司范围内的审计记录 |

`is_manufacturer`、`is_brand`、`is_distributor`、`is_agent` 和 `is_enduser` 主要影响全局业务菜单；除了平台公司不显示“界面配置”，它们不应让“我的公司”产生多套不同的信息架构。

## 3. 用户权限

符号：`管理`表示可以进入并执行授权范围内的写操作；`录入`表示可以上传或维护业务资料；`只读`表示显示但不提供写操作；`—`表示隐藏且路由拒绝访问。

界面只显示“管理员”，不向用户区分“平台管理员”和“公司管理员”。后端目标合同仍分别使用 `platform_admin` 和 `admin`，Demo 根据公司视图映射有效角色：

| 用户权限 | 平台公司视图 | 其他公司视图 | 职责 |
| --- | --- | --- | --- |
| 管理员 | `platform_admin` | `admin` | 公司所有者/最高权限账号，负责公司归属、高风险设置及授权运营人员 |
| 运营管理 | `operator` | `operator` | 代管理员处理公司日常业务和普通用户 |
| 数据录入 | `data_entry` | `data_entry` | 批量数据、入库、出库、装配/绑定及必要纠错 |
| 信息查看 | `viewer` | `viewer` | 只读查看授权公司范围内的业务信息 |

| 菜单 | 管理员 | 运营管理 | 数据录入 | 信息查看 |
| --- | --- | --- | --- | --- |
| 公司资料 | 管理 | 日常资料管理² | 只读 | 只读 |
| 公司用户 | 管理 | 管理普通用户³ | — | — |
| 界面配置 | 管理¹ | 管理¹ | — | — |
| 文件与资料 | 管理 | 管理 | 录入 | 只读 |
| 集成配置 | 管理 | 管理 | — | — |
| 操作记录 | 只读 | 只读 | — | — |

¹ 平台公司的“我的公司”不适用界面配置；平台管理员管理其他公司界面时从“客户 → 公司”进入。

² 运营管理可维护 Logo、名称和联系信息；公司归属、停用/删除、登录域名、数据区域、账号恢复和关键安全设置仍只允许管理员操作。

³ 运营管理只能创建、修改和停用 `data_entry` 与 `viewer`；不能管理自己、同级 `operator`、`admin` 或 `platform_admin`。

这些权限必须按“能力白名单 + 目标用户角色 + 公司数据范围”校验，不能在代码中实现成“管理员减去几项”。

## 4. 菜单结构

“我的公司”左侧分类固定按以下顺序组织：

1. 公司资料
2. 公司用户
3. 界面配置
4. 文件与资料
5. 集成配置
6. 操作记录

“用户权限”不作为独立分类。角色和额外数据范围属于公司用户的管理动作，应合并到“公司用户”的查看、编辑或权限面板中，避免针对同一批用户维护两个入口。

普通用户至少可以进入“公司资料”和“文件与资料”。当某个角色只有少量可见项时仍沿用同一分类导航，不创建另一套页面。

## 5. Demo 与生产实现

HTML Demo 顶部的“菜单视图”和“用户权限”选择框仅用于检查不同组合，不属于生产界面。用户权限只有管理员、运营管理、数据录入和信息查看四项；切换时同时刷新全局侧栏和“我的公司”分类菜单，并把 `company`、`role` 写入查询参数，便于直接复现组合。

后端尚需将原 `maintainer` 数据和接口合同迁移为 `operator`，不长期保留旧别名；详细迁移及验收规则见 `iot_server_backend#21` 的 `users` 表回复。

生产环境必须从认证会话读取公司、后端角色、`allowed_companies` 和 `writable_companies`，不得允许用户选择或提交自己的权限。前端统一显示名称不代表合并后端角色，菜单隐藏也不能替代命名路由守卫和后端接口校验。

全局业务菜单的公司差异见[不同公司左侧菜单规划](不同公司左侧菜单规划.md)，固定角色能力见[权限设计](../权限设计-20260827.md)，公司字段和编辑边界见[“我的公司”页面规划](url_mycompany.md)。
