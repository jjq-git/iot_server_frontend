# 列表页规范

> 最后更新：2026-09-14

本规范适用于主机、节点、静音仓、型号、公司、用户及其他后台列表页面。当前[主机列表 HTML Demo](../html/admin.html)是结构、密度和交互基准。

## 1. 页面结构

标准列表页只使用一个主 Card，并按以下顺序组织：

1. Header（`.content-card__header`）：列表名称和一句简短说明；新增按钮一般放在 Header 右侧。嵌入已有同名页面标题的列表可以省略标题，不能重复标题。
2. Filter（`.filter-bar`）：搜索、筛选、刷新操作。
3. Table：表头、数据行、加载态、空态或错误态。
4. Footer（`.content-card__footer`）：结果范围、总数和分页。

Vue 生产页面使用 `components/shared/ListPageCard.vue` 承载这四个区域；页面标题已经由 Topbar 和
全局面包屑显示时，不再在列表 Card 内重复标题。

不得把筛选、表格和分页拆成互不关联的多个 Card。Header 右侧只放新增等操作，不重复显示“共 N 台/条”等统计，数量统一放在 Footer；需要业务汇总时，应在列表 Card 之外使用独立统计组件。

**上下撑满**：列表 Card 高度撑满内容区（`.content` / 当前 `[data-page-view]` / `.content-card` 纵向 `flex` 填充），Header / Filter / Footer 固定，中间 `.table-scroll` `flex:1` 内部滚动 —— 短列表也不留大片空白，长列表表体内部滚动而非整页滚。`.table-scroll` 设有 `min-height: 390px` 下限，密度较高的表可参照此下限。设置类聚合页（如 `/mycompany` 的 `.company-profile`）只有外层 Card 撑满内容区，内部 grid 不像列表那样内部滚动。

## 2. 高度与密度

| 区域 | 桌面端高度 | 说明 |
| --- | ---: | --- |
| Header | 最小 `88px` | 容纳标题和单行说明，上下保持 `20px` 内边距 |
| Filter | 最小 `72px` | 以 `40px` 控件配合上下各 `16px` 内边距 |
| Table Header | `48px` | 排序按钮仍需保留清楚的点击区域 |
| Table Row | `56px` | 单行数据的默认密度；复杂内容应调整结构，不单独拉高某行 |
| Footer | 最小 `64px` | 容纳结果统计和 `32px` 分页按钮 |

这些尺寸通过 `src/assets/styles/_theme-vars.scss` 中的 `--list-*` 变量统一维护。页面模板不得重复写死另一套高度。窄屏允许 Filter 换行并自然增高，但不得缩小文字、表单控件或图标按钮的点击区域。

## 3. Header 与筛选

- Header 只显示标题和必要说明，不重复总数、英文装饰词或与顶部页面名称相同的冗余信息。
- 搜索框默认支持当前资源最常用的名称、编号和归属字段；placeholder 应明确范围。
- 筛选控件高度统一为 `40px`，同一行左对齐；操作区靠右。
- 下拉框隐藏浏览器默认箭头，统一调用 `icons.svg` 的下拉图标；图标与右边框保持 `10px` 间距，选择文字右侧预留 `24px`，禁止图标贴边或覆盖文字。
- 只有存在高频外部状态变化或手动重试需求时才显示刷新按钮；使用时采用纯图标，不显示“刷新”文字。刷新按钮放在 Filter 区右侧的 `.filter-bar__actions` 内。
- 新增使用“资源基础图标 + 右下角 `[+]`”组合图标；在空间稳定的后台列表中默认使用纯图标按钮。
- 新增按钮一般放在 Header 右侧（`.content-card__header`）；主机列表把新增按钮放进 Filter 区的 `.filter-bar__actions`（与刷新并列），属例外形态。
- 纯图标按钮必须提供准确的 `aria-label` 和 `title`，不能只依赖图形表达含义。

## 4. 表格与排序

- Filter 和 Table Header 使用同一个 `--color-bg-subtle` 背景，形成连续的工具与列信息区域。
- 所有可排序的数据列都在列名后显示同一个 `icon-sort`；当前排序列通过 `aria-sort="ascending"` 或 `descending` 暴露状态。
- HTML Demo 统一通过 `table-tools.js` 和 `data-sortable-table` 启用排序；业务页面只声明列的数据类型或 `data-sort-value`，不重复实现排序脚本。表格根元素必须带 `data-sortable-table`，否则排序按钮无效 —— 主机列表当前的 `<table>` 缺该属性，排序按钮点击无反应，属需修复的例外。
- 排序规则：只有带 `data-sort-type="date"` 的列按时间戳（`Date.parse`）比较，其余列一律用中文 collator（`Intl.Collator('zh-CN', { numeric: true })`）比较；单元格取值优先 `data-sort-value`，否则取文本。带 `data-sort-ignore` 的行（如空态提示行）不参与排序，恒定置于表体底部。
- “操作”列不是数据字段，不参与排序。
- 列内容默认单行显示；较长内容应通过合理列宽、截断和详情入口处理，不随意折行破坏行高。
- 可点击的资源名称统一使用 `--color-resource-link`，默认跟随主题正文色，悬停时再使用品牌色；禁止为不同资源或主题逐项写颜色覆盖。
- 状态语义：正常 / 在线态用 `.status--online`（`--color-success` 绿色语义色，在线 / 正常 / 启用 / 已启用等都在用），停用 / 离线态用 `.status--offline`（中性）。绿色只用于表达“正常”的状态语义，不用状态色做纯装饰；不能只靠颜色表达状态，必须配明确文字。
- `.status--inactive`（主机列表“未激活”行在用）在 CSS 中未定义，实际回退为中性基类 `.status`。要么补齐该修饰符定义，要么统一改用已有的 `.status--offline`。
- 空态、加载态和错误态占用 Table 区域，不改变 Header、Filter 和 Footer 的基本结构；空态行用 `data-sort-ignore` 标记，避免被排序打散。

## 5. 行操作

- 操作列优先使用 `icons.svg` 中的统一图标，常用“查看”使用眼睛图标。
- 常用“编辑”使用 `pencil` 图标，与“查看”并列显示。
- 每个操作按钮的无障碍名称必须包含动作和资源，例如“查看展厅主机 01”。
- 每行最多直接显示两个高频操作；其余操作收进统一的“更多”菜单，不继续横向堆叠。
- 删除、解绑等危险操作不能仅用颜色区分，执行前必须二次确认。

## 6. 分页与统计

- Footer 左侧显示当前范围和总数，例如“第 1–20 条，共 86 条”。
- Footer 右侧显示分页；上一页和下一页只使用 `icons.svg` 中的左右图标。
- 当前页使用品牌色文字和边界，不使用深色实底反白；不可用按钮保留位置并进入 disabled 状态，避免分页区域跳动。
- 数据为空时显示“第 0–0 条，共 0 条”或等价信息，不能保留上一次请求的数量。

Footer 统一由 `ListPageCard` 输出范围统计；服务端分页列表在右侧提供 `BasePagination`，不分页的小数据集只保留范围统计。日历等非列表视图可通过 `showFooter` 隐藏整个 Footer。

## 7. 图标与复用

- 列表页使用的搜索、筛选、刷新、新增、排序、查看、编辑和翻页图标全部来自 [`html/icons.svg`](../html/icons.svg)。
- 页面不得使用字符 `<`、`>` 代替翻页图标，不得新增零散内联 SVG，也不得直接调用风格不同的第三方图标组件。
- 主机列表定义的是共享页面结构，不是主机专属实现。其他资源列表应复用同一 List Header、Filter Bar、Data Table、Action Cell 和 Pagination 组件，只替换字段、筛选条件、权限与资源图标。
- 生产实现中，菜单可见性、按钮可见性和写操作能力仍须分别检查角色、`allowed_companies`、`writable_companies` 以及后端权限，不以 Demo 的静态显示为授权依据。

## 8. 响应式与验证

- 中等宽度下 Filter 允许换行，搜索框优先占据剩余宽度，操作按钮保持至少 `40 × 40px`。
- 窄屏下搜索、筛选和操作区按顺序纵向排列；表格保留横向滚动，不强行压缩全部列。
- 固定首列或操作列只有在实际数据验证其必要性后启用，不能为视觉效果默认增加。
- 新建或改造任一列表页时，应检查浅色主题、深色主题、键盘焦点、空数据、长文本、加载失败和窄屏横向滚动。
