# UI 图标规范

> 最后更新：2026-09-09

本文件集中记录后台应用 UI 图标的资产边界、视觉规则、业务语义和组合方式。统一图标 Sprite 见 [`html/icons.svg`](../html/icons.svg)。

## 1. 统一图标库

- 菜单、页面标题和常用操作最终统一通过 `AppIcon` 使用项目 UI 图标库。
- 所有收录图标均视为项目图标库资产，不在名称或界面中标注“自定义 / custom”。
- 允许从 [Bootstrap Icons 官方仓库](https://github.com/twbs/icons)等现成图标中选取路径，但收录后必须与自行绘制的图标使用相同命名、网格、描边和审核规则。
- 原始来源和许可证只作为内部追溯元数据保留，不在业务组件中暴露第三方图标名称。
- HTML 原型统一从 `docs/ui/html/icons.svg` 引用 symbol，不允许手工复制或另画同名 UI 图标。
- Logo、产品图片、复杂插画、设备动态图和数据可视化不进入应用 UI Sprite。
- 现有 `IconLibrary.vue` 及其 API 管理可编辑、可生成 LVGL 资源的业务图标，不作为 `AppIcon` 的运行时可变数据源。

## 2. 基础视觉规则

- 运行时图标使用 `24 × 24` 统一网格、`currentColor`、round linecap 和 round linejoin。
- 细线参考 Material Symbols Weight `100`，对应 `stroke-width: 1`，用于普通和未选中状态。
- 粗线参考 Material Symbols Weight `300`，对应 `stroke-width: 1.5`，用于选中和强调状态。
- Bootstrap 的填充路径无法仅通过 CSS 获得统一粗细，收录前需要逐个审核并按需重绘为线性版本。
- 基础图标不写死业务状态色；颜色、尺寸、粗细和状态由 `AppIcon` 与主题变量控制。
- 独立图标入口和纯图标按钮使用浅色或透明背景，不使用深色实底配白色反相图标；常态边框保持透明，键盘聚焦时只显示一层品牌色焦点框，避免双重边框。当前页码同样以品牌色边界和文字表达，不使用反白色块。
- 图标总览上方只展示可独立使用的基础图标；派生状态只在下方规则区展示。

## 3. 业务语义

- “公司”使用 `building`，“用户”使用 `people`；“客户”作为公司与人员的上级入口，使用复合图标 `customer-company-users`。
- “静音仓”使用 `soundproof-pod`：矩形舱体内包含门和声波线，不使用容易被理解为住宅或首页的 `house-door`。图标使用较细描边，门位于左下、声波位于右上，右下角不放关键细节。`house-door` 仍留在 Sprite 中，但当前无任何模板引用，作为未使用的历史遗留 symbol 保留。
- “型号”统一使用 `product-model`：标签轮廓、左侧圆孔和右侧型号编码线，同时适用于控制器型号和静音仓型号。
- “控制器”使用 `controller-system`：节点位于右上后层、主机位于左下前层，像复制图标一样叠放，表达控制器包含主机和节点。
- “主机”使用 `controller-host`：只保留两个水平、垂直居中的同心正方形，分别表示机身和屏幕。
- “节点”使用 `controller-node`：略宽的矩形盒体和顶部三个等距接头；接头只保留柱体、两条简化螺纹线和底座。
- “控制器控制台”使用 `controller-console`：带顶部状态区和三组纵向控制位的面板，表达对雷达、风机、灯光和系统参数的集中操作；不再使用过于泛化的 `sliders`。
- 低层“设备控制台”属于 CANopen、NMT、SDO 等诊断命令入口，后续应使用独立的诊断或命令图标，不与 `controller-console` 共用。
- MQTT 统一使用 `mqtt-broker`：中央 Broker、左向发布箭头和右向订阅箭头。连接配置和消息监控放在同一 MQTT 页面内。
- “系统”使用 `system-platform`：两层平台服务机架、状态点和短横线，表达发布管理、设备诊断、基础设施和平台服务密钥，不与普通“设置”共用齿轮。
- “网页界面”使用 `web-interface`：矩形内包含简化的顶部栏、左侧栏和内容线，表达浏览器中的后台页面布局。
- “LCD 操控界面”使用 `lvgl-interface`：复用主机内屏矩形，内部包含两组滑杆和两个触控按钮。滑杆使用 `2.5px` 圆角粗描边，轨道在实心圆滑块处断开；外框和底部按钮保持标准细线。
- “新增公司用户”使用 `person-add`：复用 `person` 基础轮廓并在右下角叠加统一的方形 `+` 修饰符，不另画一套人员图标。
- 登录、账号菜单和通用表单使用同一图标库中的 `envelope`、`lock`、`eye`、`eye-slash`、`check`、`save`、`upload`、`arrow-right` 和 `box-arrow-right`；其中 `envelope` 表示唯一邮箱登录标识，`save` 表示提交并保存当前表单，`upload` 表示从本地选择并上传文件，Demo 与生产页面均不得为这些操作再次绘制内联 SVG。
- 弹窗关闭统一使用 `x`，不使用字符 `×` 或由 CSS 临时绘制；关闭图标只表达关闭当前浮层，不代替删除操作。
- 列表行的“编辑”统一使用 `pencil`，与“查看”的 `eye` 保持相同网格、描边和点击区域。
- 账号入口使用 `person-circle`，个人中心使用 `person`，角色/权限使用 `shield-check`；三种语义不得复用成同一个人员图标。
- 综合账号元数据使用线性 `info` 图标；当内容同时包含时间、登录 IP 和安全记录时，不使用只表达时间的 `clock`。
- 移动端打开侧栏使用 `menu`：三条等长水平线，遵守统一线宽和圆角线帽，不再用 CSS 或字符重复绘制。

## 4. 组合图标

- 组合状态必须复用基础图标的同一 `symbol` 和样式类，只能增加裁切与修饰符，不能更换主体路径或描边参数。
- “新增”优先使用为资源预制的 `+新增` 复合 symbol（如 `person-add` / `product-model-add` / `controller-host-add`），或对没有专用复合图标的入口使用通用 `plus` 图标；`plus` 是通用“添加”字形，已在 `pods-list`、`pod-models-list`、`client-list`、`company-integrations` 以及编辑客户弹窗的“＋管理员”页签中直接引用。
- 资源的 `+新增` 变体是**预先合成并烘焙进 Sprite 的 symbol**（`person-add` / `product-model-add` / `controller-host-add`），模板按 id 直接 `<use>` 引用，不在运行时由基础图标叠加 `modifier-plus` 组合而成。
- 预合成新增图标中的 `+` 修饰区域使用宽、高约为基础图标 `1/2` 的方形底板，不使用圆形底板。
- “列表”使用资源基础图标加右下角 `modifier-list`，不为主机列表、节点列表或静音仓列表分别设计主体图标。
- `modifier-list` 不显示底板边框，只绘制三条中性灰色 `1.5px` 粗横线，不使用品牌蓝色或青色。
- 右下角裁切区从 `(10.5, 10.5)` 开始，修饰符区域从 `(12, 12)` 开始，使主体与修饰符之间保留 `1.5px` 安全间距。
- 裁切必须作用于基础矢量，不依赖白色或固定容器底色覆盖，以适应透明背景和深色主题。
- 无未读通知只显示 `bell`；有未读时复用 `bell` 并在右上角组合小型实心红色 `modifier-dot`，同时隔开红点下方的铃铛线条。

## 5. 状态与布局

- 默认图标使用中性灰色线性描边。
- 浅色模式选中态使用 `#067A7A`，并将描边从细线切换为粗线。
- 一级菜单统一显示语义明确的线性图标，包括数据、客户、控制器、静音仓和系统。
- 展开后的子菜单保留固定图标位；状态变化不能使菜单文字横向移动。
- 主题切换成对使用 `sun` 和 `moon`，显示点击后将切换到的目标主题。
- 页面标题左侧图标容器固定为 `48 × 48px`，与“页面名称 + 面包屑”两行信息的视觉高度一致；使用浅色背景和品牌深色图标，内容水平、垂直居中。
- 页面标题图标不显示左侧品牌色条。
- 图标承载容器使用直角；图标本体中的圆形、圆角线帽及产品轮廓所需弧线不受全局容器圆角规则限制。

## 6. 实现要求

- `AppIcon` 至少支持语义名称、尺寸、普通/强调线宽、装饰性隐藏标签和可访问名称。
- `modifier-list` 和 `modifier-dot` 由组件在运行时组合叠加，不为每一种资源复制完整 SVG。
- 资源的 `+新增` 变体（`person-add` / `product-model-add` / `controller-host-add`）例外：它们是预先合成好、直接烘焙进 Sprite 的独立 symbol，模板按 id 引用，不在运行时组合。
- 新增 UI 图标必须先进入统一 Sprite 和语义映射，业务页面不得直接新增 `<b-icon>` 或零散内联 SVG 图标。
- 迁移按布局公共组件、高频通用动作、业务页面分批执行，并增加图标渲染快照、深浅主题和无障碍检查。
