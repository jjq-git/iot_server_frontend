# home（首页 · 落地看板）

> 最后更新：2026-09-09

`/` 是登录后的落地页，也是侧栏品牌 Logo 的回跳目标。四类公司都可见，但**呈现内容按公司类型不同**（上排 KPI 计数卡 + 下方趋势图表，图表按 `company_dashboards` 看板配置呈现）。

> 与 `/data`（数据）的关系：`/` 是概览落地页（KPI + 关键趋势）；`/data` 是更完整的数据 / 图表页，另篇规划。

## 0. 权限

访问**只按公司类型**：平 / 静 / 中 / 终 均可进入 `/`。内容差异见下表；数据一律按登录 token 的 `company_id` + 服务端 scope 圈定，只显示本公司数据。角色（A/O/D/V）不改变可见性，只影响下钻按钮。

## 1. 上排 KPI 计数卡（按公司类型）

| 卡片     | 平  | 静  | 中  | 终  | 数据来源                                                                    |
| -------- | --- | --- | --- | --- | --------------------------------------------------------------------------- |
| 客户数   | ✓   | ✓   | ✓   | -   | `companies`（本公司下级公司数，见 `/companies/tree`）；最终用户是末端无下级 |
| 静音仓数 | ✓   | ✓   | ✓   | -   | `pods`（本公司范围内静音仓数）                                              |
| 型号数   | ✓   | ✓   | ✓   | -   | `pod_models` / `hn_models`（型号目录数）；与「型号」菜单一致，终不涉及型号  |
| 控制器数 | ✓   | ✓   | -   | -   | `hosts` + `nodes`（主机 / 节点数）；控制器是硬件，仅平台 + 厂家             |

- 每张卡片：数字 + 一句话标签 + 可选环比；有权限时点击下钻到对应列表页。
- `-` 的卡片对该类型公司**不渲染**（不是灰显）。
- **终端例外**：最终用户首页不看聚合计数，整排 KPI 卡不渲染，改为直接列「我的静音仓」，见 [§3](#3-最终用户首页我的静音仓)。

## 2. 下方趋势图表（按公司类型）

图表集与顺序由 `company_dashboards` 看板配置决定（每公司一份），下面是默认建议：

| 图表                        | 平  | 静  | 中  | 终  | 说明                                        |
| --------------------------- | --- | --- | --- | --- | ------------------------------------------- |
| 设备在线率趋势              | ✓   | ✓   | -   | -   | 主机 / 节点在线率（有控制器的公司才有意义） |
| 告警统计 / 趋势             | ✓   | ✓   | -   | -   | 设备告警级别与数量                          |
| 静音仓使用趋势              | ✓   | ✓   | ✓   | ✓   | 使用次数 / 平均时长（人人关心自己的仓）     |
| 本公司静音仓状态 / 使用时长 | -   | -   | -   | ✓   | 终端：只看自己在用的仓                      |

- 空态 / 加载态 / 错误态占图表区域，不改 KPI 卡结构。
- 图表字号不随视口缩放；ECharts 文字用 `getFontScale()` 跟随全局字号（见前端架构约定）。
- **终端例外**：最终用户不看设备类图表；其首页图表只保留「静音仓使用趋势」+「本公司静音仓状态 / 使用时长」，且位于「我的静音仓」之下（见 §3）。

## 3. 最终用户首页（我的静音仓）

最终用户是静音仓的直接使用者，首页**以静音仓为中心**，不呈现聚合 KPI 与设备/告警类图表。与侧栏「我的静音仓」一致（见 [页面清单说明](README.md#页面清单与访问权限按公司类型)）。

- **主体 = 我的静音仓卡片**：列出该用户可访问的每台静音仓，**有多型号按型号分组**（如「会议仓 Pro」/「静音舱 Lite」），只有一个 / 无型号则平铺。
- **每张仓卡片**：仓名 + 位置 + 运行状态（在线 / 离线、空闲 / 使用中）+「进入控制」入口；点卡片进**该仓控制页**。
- **下方图表**：仅「静音仓使用趋势」与「本公司静音仓状态 / 使用时长」，只统计本人在用的仓。
- 数据按登录 token 的 `company_id` + scope 圈定；卡片由后端返回的可访问 `pods` 动态生成，分组依据 `pod_models`。

## 4. 结构与交互

- 顶部页面标题 = 当前 `company_name` + `building` 图标；内容区直接进入 KPI 卡 + 图表，不重复公司身份块。
- 布局：上排 KPI 卡用栅格（按卡片数 2/3/4 列自适应，窄屏折叠）；下方图表按 `company_dashboards` 排布，遵循 [Card 布局规范](widgets/cards.md)。
- 数据只读展示；下钻按钮按角色 / scope 收紧（无权限隐藏）。

## 5. 后端 / API 参考（未逐条核对）

> 供后端实施参考；页面功能以上文为准。前端 `dev` 分支已落地看板实现，本节以其契约为准。

- **前端看板组件（dev 已实现）**：KPI 卡 = `MetricCardWidget`（模块 `stats_preview`），图表 = `ChartWidget`，12 栏 `DashboardGrid` + `WidgetRenderer` 分发；模块 → 图表类型映射见 [configResolver.js](../../src/services/dashboard/configResolver.js)。
- **KPI 汇总**：`GET /dashboard/summary`（按公司类型返回本公司应显示的计数集），见 [dashboard.js](../../src/api/dashboard.js)。
- **图表数据**：`POST /dashboard/chart-data/query`（按模块 `source_key` / `metric_key` / `aggregation` / `interval` / `range` 查询）。
- **看板配置**：公司 `dashboard_modules` 模板（即 `company_dashboards`，每公司一份，决定模块集、顺序与 12 栏布局）；缺省经 `configResolver` 兜底。
- **模块键**：`stats_preview`（KPI）、`device_online_rate`（在线率 line）、`alert_trend` / `alert_stats`（告警）、`pod_usage_trend`（静音仓使用 bar）、`pod_usage_distribution`、`file_usage_stats`、`detailed_stats`。
- **计数分项来源**：客户数→`companies`（`/companies/tree`）；静音仓数→`/pods`；型号数→`/pod-models`、`/hn-models`；控制器数→`/hosts`、`/nodes`。均按当前 `company_id` + scope 过滤。
