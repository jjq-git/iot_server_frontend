# 样式规范

> 适用范围：`iot_server_frontend/docs/ui/html/`
>
> 最后更新：2026-09-09

本文规定 HTML UI Demo 的视觉与交互呈现。文件放置和数据字段规则见[前端代码架构](frontend-architecture.md)。

## 1. 设计基线

- 后台界面保持安静、紧凑、工作导向，优先支持扫描、比较和重复操作。
- 页面沿用现有后台壳层、内容宽度和信息密度，不使用营销页式 Hero、装饰性大卡片或无业务意义的视觉元素。
- 页面区块保持平整，不把页面每一段都做成浮动 Card，也不嵌套 Card。
- 所有界面容器统一使用直角，由 `tokens.css` 的 `--radius: 0` 控制；通知红点、状态符号和图标本体的必要曲线除外。

## 2. 设计变量

`assets/css/tokens.css` 是颜色、间距、尺寸、阴影和圆角的唯一变量来源。

必须使用：

- `--color-*`：品牌、背景、文字、边框、状态和遮罩语义色。
- `--space-*`：`4/8/12/16/20/24/32px` 间距序列。
- `--list-*`：列表 Header、Filter、表头、数据行和 Footer 尺寸。
- `--sidebar-width`、`--topbar-height`：后台壳层尺寸。
- `--radius`、`--shadow-popover`：全局形状与浮层阴影。

不得在页面模板写内联颜色，不得为单个页面复制一套颜色或间距变量。确需新增语义变量时，先确认有明确的跨主题含义，并同时定义浅色和深色值。

## 3. 页面布局

- 后台页面复用 `.app-shell`、`.workspace`、`.content` 和现有 Topbar/Sidebar。
- 页面标题只在顶部壳层或内容 Header 出现一次，不能在相邻区域重复。
- 内容区按任务组织，保持稳定的对齐线和间距节奏。
- 固定格式控件使用明确的宽度、网格轨道或 `min/max` 约束，加载、错误、长文本和状态变化不能推动整体布局跳动。
- 页面最小支持宽度为 `320px`；窄屏优先重排和横向滚动，不缩小文字或点击区域。

## 4. 列表页面

所有列表必须遵守[列表页规范](../widgets/lists.md)。当前主机列表是结构与密度基准。

标准顺序：

```text
Header → Filter → Table → Footer
```

核心要求：

- 一个列表使用一个主内容容器，不把筛选、表格和分页拆成互不关联的 Card。
- Header 最小 `88px`，Filter 最小 `72px`，表头 `48px`，数据行 `56px`，Footer 最小 `64px`。
- Filter 与表头使用同一浅背景，搜索、筛选和操作保持同一 `40px` 控件高度。
- 数量和分页统一放在 Footer；Header 不重复总数。
- 空态、加载态和错误态占用表格区域，不改变其他区域结构。
- 行操作不超过三个时直接显示，更多操作进入“更多”菜单。
- 删除、解绑等危险操作必须二次确认，不能仅靠红色表达危险。

## 5. 表单与弹窗

- 字段按业务阅读顺序排列，相关字段使用两列网格；窄屏回落为单列。
- Label、输入框、说明和错误信息保持稳定顺序；必填状态不能只靠颜色表达。
- 输入框、选择器和主按钮的默认高度为 `40px`，点击目标不得小于 `40 × 40px`。
- 布尔值使用 Switch/Checkbox，有限选项使用 Select 或分段控件，数值使用匹配语义的输入控件。
- 非开关复选框的选中色使用品牌实底 `#067a7a`（`admin.css` 中 `input[type="checkbox"]:not([role="switch"]) { accent-color: var(--color-brand-solid) }`，`--color-brand-solid` 定义在 `tokens.css`）；`role="switch"` 的开关不受此规则约束，保留 Switch 自身样式。
- 系统生成、不可变或不允许当前操作修改的字段显示为只读，不伪装成可编辑输入框。
- Modal Header 只包含标题、必要的一句业务说明和关闭按钮；Footer 放取消与主操作。
- Modal 主操作使用明确动词，例如“创建型号”“保存用户”“确认删除”，避免笼统的“确定”。
- 校验错误靠近对应字段；跨字段或服务器冲突放在表单顶部的统一错误区域。
- 开发交接信息不得显示在表单说明中。

## 6. 按钮和图标

- 所有图标统一引用 [`icons.svg`](icons.svg)，不得引入外部图标包、字符图标或普通内联 SVG 路径。
- 熟悉的工具动作优先使用纯图标按钮；不熟悉的动作使用图标加文字，并提供准确的 `title`。
- 纯图标按钮必须有包含动作和资源的 `aria-label`，例如“编辑 P-0050”。
- 新增资源使用“资源基础图标 + 右下角 `[+]`”的统一组合图标。
- 独立图标入口和纯图标按钮使用浅色或透明背景配中性/品牌色图标，不使用品牌色实底加白色反相图标。
- **列表页 Header 的新增按钮、设置卡的保存按钮等纯图标入口，统一用 `button--secondary button--icon-only`**（浅底 + 边框 + 中性/品牌图标），三者一致；**不要**用 `button--primary` 做纯图标按钮（实底反相图标只会出现在带文字的主操作上）。基准示例：设置页「保存资料」按钮、型号列表「导入型号」按钮。
- 主要文字按钮才可以使用品牌实底（`button--primary`），且必须带明确动词文案（如弹窗页脚“创建客户”“保存用户”）；次要按钮使用表面背景和边框（`button--secondary`）。
- Disabled 状态保留控件尺寸和位置，避免布局变化。

## 7. 表格、文字与状态

- 表格以单行扫描为主，长内容通过合理列宽、截断和详情入口处理。
- 数据编号、哈希、协议地址和版本号使用等宽字体样式。
- 表格内标题和标签使用紧凑字号，不使用 Hero 级大字。
- 字号不随视口宽度缩放，字距保持默认值。
- 状态必须显示明确文字，不能只依赖颜色；列表状态优先使用统一中性样式。
- 成功、警告和错误色仅用于确有语义的反馈，不把品牌色或状态色当装饰。
- 链接默认跟随正文色或 `--color-resource-link`，悬停时再使用品牌色。
- 文案必须适配容器；超长编号允许安全截断或换行，不能覆盖相邻内容。

## 8. 主题与可访问性

- 新样式必须在 `:root` 和 `html[data-theme="dark"]` 下都能正确显示。
- 使用语义色变量保证主题切换，不基于具体十六进制颜色判断业务状态。
- 所有按钮、链接和表单控件必须有清晰的 `:focus-visible` 状态。
- 弹窗关闭按钮去除浏览器默认蓝框：`base.css` 用 `:focus:not(:focus-visible) { outline: none }` 抑制鼠标或程序化聚焦（如弹窗打开时自动聚焦关闭按钮）的默认蓝框；键盘 `:focus-visible` 仍显示品牌色 focus 环，不影响键盘可达性。
- 图标不能是动作的唯一可访问名称；装饰图标设置 `aria-hidden="true"`。
- 动态反馈使用合适的 `aria-live`，Modal 标题通过 `aria-labelledby` 关联。
- 尊重 `prefers-reduced-motion`；动画只用于状态反馈，不影响功能完成。
- 浅色和深色主题均需检查文字、边框、Disabled 状态和危险操作的对比度。

## 9. 响应式

- 桌面端保持紧凑稳定的多列布局。
- 中等宽度允许 Filter 和表单字段换行，搜索框优先占据剩余宽度。
- 窄屏下表单回落为单列，操作按钮保持完整点击面积。
- 宽表格保留横向滚动，不强行压缩所有列或显著缩小字体。
- Modal 使用 `min()`、可用视口宽度和必要的内容滚动，不能超出屏幕。
- 必须用长名称、长编号、错误文本和空数据检查内容不会重叠。

## 10. 样式检查清单

- [ ] 只使用 `tokens.css` 中的语义变量。
- [ ] 页面复用已有壳层、基础控件和页面族样式。
- [ ] 没有 Card 嵌套、装饰性浮层或单页私有视觉体系。
- [ ] 列表符合 `lists.md` 的结构、密度和操作规则。
- [ ] 按钮、图标、状态和危险操作表达一致。
- [ ] 浅色、深色、320px 窄屏和桌面宽屏均已检查。
- [ ] 键盘焦点、ARIA 名称、动态反馈和 Reduced Motion 均可用。
- [ ] 长文本、空态、加载态、错误态不会导致布局错位。
