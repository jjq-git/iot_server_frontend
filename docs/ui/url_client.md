# client（客户 · 下级公司管理）

> 最后更新：2026-09-09

`/client` 管理本公司的**下级客户公司**（公司树中 `parent_com_id` 指向本公司的分支，按登录 token 的 company scope 圈定）。列表 + 新建 + 详情下钻。这是**数据录入人员的核心工作页之一**：把新客户公司录入系统并为其建管理员，再由该客户向下建静音仓 / 建设备。

> 与「我的公司」的关系：[/mycompany](url_mycompany.md) 管本公司**自身**信息；`/client` 管本公司的**下级**公司。二者字段同源 `companies`，视角相反（自身 vs 下级）。
> 原型：[client-list.tpl](html/templates/pages/client-list.tpl)；数据模型：[companies.md](../../../iot_server_backend/docs/数据模型/companies.md)。

## 0. 权限

### 公司权限（按公司类型）

平＝平台、静＝静音仓厂家、中＝中间商（渠道 / 分销）、终＝最终用户。

| 页面 | 平 | 静 | 中 | 终 |
| --- | --- | --- | --- | --- |
| 客户 `/client` | ✓ | ✓ | ✓ | - |

- 终端是公司树末端、无下级，故无此页（对齐 [页面清单](README.md#页面清单与访问权限按公司类型)）。
- 每类公司只能看/管**自己的下级**，看不到平级或上级；由后端按 `current_com_id` + 公司树圈定，前端不做数据边界。

### 角色权限（按角色）

A＝管理员、O＝运营管理、D＝数据录入、V＝数据查看。**RW**＝可读写、**RO**＝只读、**-**＝不可操作。客户录入是 **D 的核心职责**。

| 操作 | A | O | D | V |
| --- | --- | --- | --- | --- |
| 查看列表 / 详情 | RO | RO | RO | RO |
| 新建客户（含建管理员） | RW | RW | RW | - |
| 编辑客户资料 | RW | RW | RW | - |
| 停用 / 启用客户 | RW | RW | - | - |

> 生产以后端 scope / `require_roles` 为准，前端只做体验层门禁。危险操作（停用整个客户公司）限管理员 / 运营，且二次确认。

## 1. 客户列表

列表遵循[列表页规范](widgets/lists.md)：Header → Filter → Table → Footer。

### 1.1 列

| 列 | 字段 | 说明 |
| --- | --- | --- |
| 客户名称 | `short_name`（主）/ `company_name`（副） | 简称做标题，全称次要展示；点行进详情 |
| 客户编码 | `company_code` | 只读 `CO-XXXXXX`，等宽字体，后端生成 |
| 客户类型 | `is_pod_manufacturer` / `is_brand` / `is_channel_partner` / `is_enduser` | 由业务角色派生的类型徽标（MF 厂家 / BR 品牌 / CP 渠道 / EU 终端）；可多角色 |
| 联系人 | `contact_person`（+ `contact_phone` / `contact_email`） | 公司联系人，显示姓名 + 电话；**与"公司管理员用户"是两个概念**（后者见 §2.1） |
| 地点 | `location_id` → `locations` | 派生只读的国家 / 地址，不直接存公司行 |
| 状态 | `is_active` | 正常 / 停用，状态用明确文字不只靠颜色 |
| 创建时间 | `created_at` | 审计时间 |
| 操作 | — | 查看（点行即可）/ 编辑（列表只留编辑；停用 / 启用在编辑弹窗的账号状态里改） |

### 1.2 筛选

- 搜索：`short_name` / `company_name` / `company_code` / 联系人。
- 类型筛选：按业务角色（厂家 / 品牌 / 渠道 / 终端）。
- 状态筛选：正常 / 停用。
- 数量与分页放 Footer，Header 不重复总数。

## 2. 新建 / 编辑客户

### 2.1 新建（仅公司信息）

新建客户**只建公司**（`companies` 行，`parent_com_id` 由后端按登录公司隐式写入），**不在此弹窗建管理员**。字段：

| 字段 | 编辑 | 约束 |
| --- | --- | --- |
| `company_name` | 必填 | 公司正式全称 |
| `short_name` | 必填 | 页面标题用简称，不可置空 |
| 客户类型（`is_*`） | 必选至少一个 | 选项**按当前公司类型限定**（见「谁能建谁」）；`is_enduser` 与其他项**互斥**；客户不能改自身身份 |
| `contact_person` / `contact_phone` / `contact_email` | 可选 | 公司联系人（列表 / 详情展示）；**与管理员账号是两个概念** |
| `location_id` | 可选（弹窗选择） | 从 `locations` 选择 + 备注；国家 / 地址派生只读 |
| `is_active` | 可编辑 | 默认启用 |
| 🔴 `domain` | 平台可配、其余只读 | 目标新增（单一入口 URL，含 `https://`）；登录入口前缀 `https://pods.dengtec.com/` + subpath，可选填，无要求默认分配 |
| `company_code` | 只读 | 后端 `CO-` + 6 位 Crockford Base32 生成、全局唯一；标题说明处展示 |

> **管理员单独加**：管理员账号（`users` `role=admin`）**不在新建公司弹窗里建**，改在客户详情 / 「人员」页操作 —— 没有管理员时显示「增加管理员」，有则显示名称 + 「编辑」（见 §3）。这与「联系人」（`contact_*`）是两个概念。

### 2.2 编辑

编辑客户改公司信息（全称 / 简称 / 业务角色 / 联系人 / 地点 / 状态）；`company_code`、`domain` 只读。**管理员账号不在此弹窗改**，增删用户 / 改名 / 重置密码走该客户「人员」页的用户接口。

### 谁能建谁（公司树向下一层）

- 平台（PF）→ 静音仓厂家 / 品牌 / 渠道 / 最终用户。
- 静音仓厂家（MF）→ 其下级（渠道 / 品牌 / 最终用户）。
- 中间商 / 渠道（CP）→ 最终用户 / 下级渠道。
- 非平台公司创建时至少选一个角色；最终用户是末端，不能再建下级。

## 3. 客户详情（下钻）

点列表行进客户详情，只读展示该 `companies` 行的完整资料（含联系人）；编码放在标题下方，客户类型 / 登录入口 / 创建时间各占半宽。并按权限提供下钻入口：

- 该客户的**下级公司**（继续走 `/client` 视角，`parent_com_id` = 该客户）。
- 该客户名下的**静音仓 / 设备**（按公司类型与 scope 决定是否可见）。
- 该客户的**人员**（管理员账号在此维护：改资料 / 重置密码 / 增删用户）。

> 详情不重复编辑本公司自身信息（那属于 `/mycompany`）；这里始终是"看/管下级"。

## 4. 后端 / API 参考（未逐条核对）

> 供后端实施参考；页面功能以上文为准。字段语义以 [companies.md](../../../iot_server_backend/docs/数据模型/companies.md) 目标态为准。

- **列表 / 树**：`GET /api/v1/companies`（按 token company scope 过滤）、`GET /api/v1/companies/tree`、`GET /api/v1/companies/{company_id}/children`（均返回 `short_name`）。列表的"联系人"列 = `companies.contact_person`（+ 电话 / 邮箱），随公司行返回；公司管理员用户（`role=admin`）单独在该客户「人员」页管理，不在本列。
- **新建（两步）**：① `POST /api/v1/companies`——不接收 `company_code`；`company_name` / `short_name` 必填；非平台公司至少一个业务角色；`parent_com_id` 由后端按当前公司写入。② `POST /api/v1/users`——`company_id` = 新公司、`role=admin`、`must_change_password` 默认 true。🔴 两步最好由后端包一个事务接口（建公司即建管理员），避免建了公司却没管理员的中间态。
- **编辑**：`PUT /api/v1/companies/{uuid}`——编码不可改、`short_name` 不可置空。管理员账号改动走 `users` 接口（`PUT /users/{uuid}`、管理员重置密码接口），不在公司更新接口内。
- **停用**：走 `is_active`；停用影响整个客户公司访问，需明确二次确认。
- **派生字段**：`logo_url`（由 `logo_file_id` 派生）、国家 / 地址（由 `location_id → locations` 派生）；请求不再直接写 `country` / `region` / `data_region` / `address`（已删）。
- 🔴 **目标态差距**：`domain`（合并原 `subdomain` / `subpath` / `custom_domain` / `domain_verified` / `company_slug`）与 `slogan` 为 2026-09-08 目标新增，后端 `CompanyResponse` / 创建 / 更新 Schema 待增补；接入前 Demo 按目标展示，用 `<!-- Handoff -->` 记缺口，不退回旧字段。
